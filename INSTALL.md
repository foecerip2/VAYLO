# Установка VPN-сервиса на VPS

Инструкция для чистого сервера **Ubuntu 22.04 / 24.04** (подойдёт и Debian 12). Всё ставится двумя командами: установщик сам поставит Docker, соберёт проект, выпустит HTTPS-сертификаты и создаст администратора. Отдельным скриптом можно поставить панель **Remnawave**.

---

## 0. Что понадобится

| Что | Зачем |
|---|---|
| VPS: 2 vCPU, 2 ГБ RAM, 20 ГБ диска (1 ГБ RAM хватит, но сборка будет долгой) | Для панели, API, бота, БД |
| Домен (например `example.com`) | HTTPS для Mini App, админки и панели |
| Токен Telegram-бота | Создаётся в @BotFather |
| Отдельные VPS под VPN-ноды (позже) | Сами VPN-серверы; устанавливаются из панели Remnawave |

> Нода VPN и сервер с панелью — **разные** серверы. На сервере с панелью порты 80 и 443 должны быть свободны.

---

## 1. DNS: создайте A-записи

В панели вашего регистратора/DNS-хостинга создайте записи, указывающие на **IP вашего VPS**:

| Запись | Назначение |
|---|---|
| `app.example.com` | Mini App, личный кабинет, приём платежей |
| `admin.example.com` | Админка |
| `panel.example.com` | Панель Remnawave |
| `sub.example.com` | Страница подписок (ссылки, которые получают клиенты) |

Если домен на Cloudflare — отключите проксирование (серое облачко), иначе Caddy не выпустит сертификат. Подождите 2–10 минут, пока записи применятся. Установщик сам проверит DNS и предупредит.

---

## 2. Создайте бота в Telegram

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot` → задайте имя и username (например `my_vpn_bot`).
2. Скопируйте **токен** вида `123456789:AAH...`.
3. (Необязательно) `/setuserpic`, `/setdescription`, `/setabouttext` — оформление.
4. Кнопка «Открыть» (Mini App) и команды бота настроятся **автоматически** при старте бота.
5. (Необязательно) Прямая ссылка на Mini App: BotFather → `/newapp` → выберите бота → URL: `https://app.example.com`.

## 3. Загрузите проект на сервер

С вашего компьютера (замените IP и имя архива):

```bash
scp vpn-platform.zip root@IP_СЕРВЕРА:/root/
ssh root@IP_СЕРВЕРА
apt-get update && apt-get install -y unzip
unzip vpn-platform.zip -d /root/vpn-platform
cd /root/vpn-platform
```

## 4. Запустите автоустановщик

### Вариант А — всё на одном сервере (рекомендуется)

```bash
sudo bash scripts/install.sh
```

Скрипт спросит базовый домен, токен бота, email для входа в админку и поставит ли он Remnawave. Для запуска без вопросов:

```bash
sudo bash scripts/install.sh \
  --domain example.com \
  --bot-token 123456789:AAH... \
  --admin-email you@example.com \
  --remnawave install \
  --yes
```

Что делает установщик:

1. Проверяет токен бота и DNS, ставит Docker, если его нет.
2. Ставит Remnawave (если выбрано): панель, страницу подписок, создаёт суперадмина и API-токен.
3. Генерирует все секреты и пишет `/opt/vpn-platform/deploy/.env` (права 600).
4. Собирает образы и запускает: PostgreSQL, Redis, API, воркер, бот, шлюз Caddy с HTTPS.
5. Создаёт владельца админки и сохраняет все адреса и пароли в `/opt/vpn-platform/CREDENTIALS.txt`.
6. Включает ежедневный бэкап БД (03:30, папка `/opt/vpn-platform/backups`) и открывает порты в `ufw`, если он активен.

Первая сборка занимает 3–8 минут.

### Вариант Б — Remnawave уже стоит (на этом или другом сервере)

```bash
sudo bash scripts/install.sh --domain example.com --bot-token ... --admin-email ... \
  --remnawave external --rw-url https://panel.example.com --rw-token ТОКЕН_API --yes
```

API-токен создаётся в панели: **Настройки → API-токены**.

### Вариант В — Remnawave ставится отдельно (только панель)

```bash
sudo bash scripts/install-remnawave.sh --panel-domain panel.example.com --sub-domain sub.example.com
```

Скрипт поставит Docker, панель, страницу подписок и собственный Caddy с HTTPS, создаст суперадмина и API-токен и выведет их. Параметры: `--proxy none` (без прокси — для случая, когда он уже есть), `--dir`, `--admin-user`, `--output`. Повторный запуск безопасен.

## 5. После установки

### 5.1 Войдите в админку

Откройте `https://admin.example.com`, войдите с email и паролем из `CREDENTIALS.txt`. Сразу включите 2FA: **Настройки → Безопасность**.

### 5.2 Настройте Remnawave (ноды и сквад)

1. Откройте `https://panel.example.com`, войдите данными из `CREDENTIALS.txt`.
2. **Nodes → Create**: добавьте ноду и выполните на VPS-ноде команду, которую покажет панель (ставится `remnanode`).
3. Создайте **Config Profile** с inbound (например VLESS Reality), затем **Internal Squad**, включающий этот inbound.
4. В админке VPN-сервиса: **Настройки → Remnawave** → нажмите «Проверить подключение». При необходимости укажите UUID сквада (иначе берётся первый).
5. Вкладка **Ноды** в админке покажет серверы и онлайн-статус.

### 5.3 Подключите платёжные системы (Настройки → Платежи)

**ЮKassa**
1. В кабинете yookassa.ru создайте магазин. Скопируйте **shopId** и создайте **секретный ключ** (Интеграция → Ключи API).
2. В админке вставьте shopId и ключ, включите переключатель, нажмите «Сохранить», затем «Проверить подключение».
3. В кабинете ЮKassa: **Интеграция → HTTP-уведомления** → адрес `https://app.example.com/api/v1/webhooks/yookassa` (он показан в админке с кнопкой «Копировать»), события `payment.succeeded` и `payment.canceled`.
4. Если у вас подключена онлайн-касса — включите «Отправлять чек (54-ФЗ)» и укажите ставку НДС.

**Platega**
1. В кабинете platega.io создайте магазин, возьмите **Merchant ID** и **секретный ключ**.
2. В админке вставьте их, выберите способы оплаты (СБП, карты, международные карты, крипта), включите, сохраните, проверьте подключение.
3. В настройках магазина Platega укажите callback: `https://app.example.com/api/v1/webhooks/platega`.

**RollyPay** (СБП, карты РФ, крипта; деньги на кассу приходят в USDT)
1. В кабинете rollypay.io создайте **кассу (терминал)**. В разделе «Интеграция» возьмите **Terminal ID**, **API-ключ** (`rpk_live_…`, виден только при выпуске) и **секрет подписи вебхуков**.
2. В админке → Настройки → Платежи → RollyPay вставьте оба значения, выберите кнопки оплаты, включите и нажмите «Проверить подключение».
3. В настройках кассы RollyPay укажите callback: `https://app.example.com/api/v1/webhooks/rollypay`.
4. Для пробы включите «Тестовый режим», сделайте платёж и подтвердите его на тестовой странице RollyPay; затем выключите тестовый режим.

Как это работает: API `https://api.rollypay.io/api/v1`, авторизация `X-API-Key` + одноразовый `X-Nonce`, платёж создаётся `POST /payments` (сумма строкой «199.00», `order_id` = id нашего платежа). Callback подписан: `X-Signature` = HMAC-SHA256 от `X-Timestamp + "." + тело` ключом signing_secret; запросы старше 5 минут отклоняются, а статус платежа дополнительно сверяется запросом `GET /payments/{id}`. Если callback потерялся, воркер опрашивает незавершённые платежи сам.

Секретные ключи хранятся в базе в зашифрованном виде и в админке всегда скрыты (`********`).

> Даже без webhook платёж не потеряется: воркер каждую минуту опрашивает провайдеров по незавершённым платежам. Webhook ускоряет выдачу доступа.

### 5.4 Тарифы, пробный период, рефералы

- **Тарифы** — создайте/измените цены, сроки, лимиты трафика и устройств. Стартовые тарифы создаются автоматически.
- **Настройки → Пробный и рефералы** — длительность и лимиты триала, награда за приглашение.
- **Настройки → Основное** — название сервиса, ссылки на поддержку и канал.

### 5.4a Новое в версии 2: настройка функций

- **Обязательная подписка на канал** — Настройки → «Подписка на канал»: добавьте канал (`@username` или `-100…`), **сделайте бота администратором этого канала**, включите переключатель. Без подписки закрыты бот и Mini App (кроме администраторов). Если бот не админ канала, проверка пропускается — клиенты не блокируются по ошибке.
- **Админ-меню в боте и Mini App** — Настройки → Администраторы: укажите **Telegram ID** администратора (узнать: @userinfobot). После этого в боте появится кнопка «Админ-панель», а в Mini App — Профиль → «Админ-панель» (обзор, пользователи, платежи, мониторинг, техработы).
- **Пополнение баланса** — Настройки → «Пополнение»: минимум/максимум, быстрые суммы и бонусные ступени (например, от 500 ₽ — +5%). Если денег на тариф не хватает, клиенту предлагается «Пополнить и купить» — покупка завершается сама.
- **Докупки** (раздел «Докупки»): доп. устройства и доп. трафик (для тарифов с лимитом трафика). **Премиум-локации**: создайте в Remnawave отдельный Internal Squad с нодой нужной страны → в «Докупки → Локации» привяжите его (выбор из списка сквадов) → создайте пакет «Локация X, N ГБ» с ценой. Покупка выдаёт доступ к скваду и добавляет N ГБ к общему лимиту.
- **Рефералы** — 2 уровня, ранги (чем больше друзей, тем выше процент и бонус-дни), партнёрские ссылки со статистикой переходов/оплат, бонусы на баланс при регистрации. Всё в разделе «Рефералы» и Настройки → «Пробный и рефералы».
- **Квесты** — раздел «Квесты»: ежедневный бонус с серией, подписка на канал, приглашение друзей, первая покупка и т. д.; награда — дни или деньги на баланс.
- **Автомониторинг** — раздел «Мониторинг»: каждую минуту проверяются БД, Remnawave, ноды, ЮKassa, Platega, RollyPay, Telegram и «зависшие» платежи. Об отказах приходит сообщение в Telegram администраторам (по их Telegram ID) и/или в доп. чат. Опционально — автоматические техработы, если Remnawave недоступна.
- **Автопродление** — клиент включает в профиле; за 3 дня до конца подписка продлевается с баланса.
- **Оформление** — Настройки → «Оформление»: акцентный цвет, логотип, баннер в приложении.

### 5.5 Проверьте всё глазами клиента

1. Откройте бота → `/start` → «Попробовать бесплатно».
2. Откройте Mini App → «Подключиться»: ссылка подписки должна открываться и добавляться в VPN-клиент (Happ, Incy, Streisand и др. — список можно менять в коде `apps/app/src/lib/clients.ts`).
3. Купите тариф минимальной суммой (или создайте промокод на 100% скидки в админке и проверьте выдачу).
4. В админке: **Платежи** → платёж со статусом «Оплачен».

## 6. Обслуживание

```bash
cd /opt/vpn-platform/deploy
docker compose ps                    # состояние контейнеров
docker compose logs -f api           # логи API (также: worker, bot, gateway)
docker compose restart api worker    # перезапуск
```

**Обновление проекта** (после замены файлов новой версией):

```bash
sudo bash scripts/install.sh --update      # из распакованной новой версии
```

Миграции БД применяются автоматически (в версии 2 добавляются таблицы квестов, локаций, партнёрских ссылок, мониторинга), перед обновлением делается бэкап. Данные и настройки сохраняются.

**Очистка мусора (чтобы не забивался диск).** Установщик включает еженедельную очистку (воскресенье 04:15) и запускает её после каждого `--update`: удаляются висячие и старые неиспользуемые Docker-образы, кэш сборки старше 3 суток, остановленные контейнеры, переполненные логи, старые бэкапы (оставляются 3 последних и всё моложе 30 дней), кэш apt и старые записи журнала. Docker-очистка затрагивает только объекты проекта (метка `com.docker.compose.project=vpn`) и висячий кэш сборки; образы и сети Remnawave не трогаются. Логи контейнеров ограничены 10 МБ × 3. Тома с базой и Redis, `.env` и свежие бэкапы не затрагиваются. Вручную:

```bash
sudo bash /opt/vpn-platform/scripts/cleanup.sh          # обычная очистка
sudo bash /opt/vpn-platform/scripts/install.sh --cleanup # глубокая: все неиспользуемые образы проекта (включая :prev)
```

**Бэкап и восстановление:**

```bash
sudo bash /opt/vpn-platform/scripts/backup.sh             # вручную (хранятся последние 14 копий каждого вида)
sudo bash /opt/vpn-platform/scripts/restore.sh /opt/vpn-platform/backups/vpn-XXXX.sql.gz   # флаг --yes — без вопроса
```

В папке `backups` (права 600) создаются три вида файлов:

- `vpn-ДАТА.sql.gz` — дамп БД проекта;
- `vpn-config-ДАТА.tar.gz` — `deploy/.env`, `deploy/caddy.d/*.caddy`, `CREDENTIALS.txt`, а также `.env` и compose-файлы Remnawave из `/opt/remnawave`. Без `deploy/.env` дамп бесполезен: в нём пароль базы и `APP_SECRET` (ключ шифрования настроек, ключей платёжных систем);
- `remnawave-db-ДАТА.sql.gz` — дамп БД панели Remnawave (если она стоит на этом сервере; сбой этого шага — только предупреждение).

Перед каждым `--update` бэкап делается автоматически (метка `pre-update` в имени файла).

**Восстановление.** `restore.sh` проверяет архив, делает страховочный бэкап текущей БД (метка `pre-restore`), загружает дамп во временную базу и только при успехе подменяет ею рабочую; при любом исходе запускает `api`, `worker`, `bot` обратно и очищает очереди BullMQ в Redis. Настройки восстанавливаются вручную, если сервер новый или `.env` потерян:

```bash
sudo tar -xzf backups/vpn-config-ДАТА.tar.gz -C /      # вернёт файлы на прежние места (opt/vpn-platform/deploy/.env и др.)
sudo bash /opt/vpn-platform/scripts/install.sh --update  # поднимет контейнеры
sudo bash /opt/vpn-platform/scripts/restore.sh /opt/vpn-platform/backups/vpn-ДАТА.sql.gz
```

Дамп Remnawave (при необходимости): `gunzip -c backups/remnawave-db-ДАТА.sql.gz | docker exec -i remnawave-db psql -U postgres -d postgres` (пользователь и база — из `POSTGRES_USER`/`POSTGRES_DB` в `/opt/remnawave/.env`); панель при этом лучше остановить: `cd /opt/remnawave && docker compose stop remnawave`.

**Копируйте бэкапы за пределы сервера** (другой сервер, облако, `scp`/`rsync` по cron): копия на том же диске не спасёт при потере VPS. В архиве настроек лежат секреты — храните его так же бережно, как сам `.env`.

**Откат неудачного обновления.** Перед сборкой установщик помечает текущие образы тегом `:prev`. Если после `--update` API не стал healthy за 120 с, будут показаны логи и предложен откат (в неинтерактивном режиме — выведена команда отката). Если `.env` потерян, а том базы остался, установщик откажется ставить заново — сначала верните `.env` из бэкапа.

**Сброс пароля владельца админки:**

```bash
cd /opt/vpn-platform/deploy
docker compose exec api node dist/cli.js create-admin you@example.com НОВЫЙ_ПАРОЛЬ owner
```

(для существующего email пароль заменяется и 2FA отключается).

## 7. Решение проблем

| Симптом | Что проверить |
|---|---|
| Сайт не открывается по HTTPS | DNS-записи (A на IP сервера, без проксирования); открыты ли порты 80/443 в файрволе провайдера; `docker logs vpn-gateway` |
| Установщик пишет «порт 80 занят» | Остановите nginx/apache: `systemctl disable --now nginx apache2` |
| Бот не отвечает | `docker compose logs bot`; верный ли токен; в `.env` корректный `WEBHOOK_URL`; открывается ли `https://app.example.com/api/v1/health` |
| «Не удалось связаться с Remnawave» (502) | Админка → Настройки → Remnawave → «Проверить подключение»; запущена ли панель: `docker ps | grep remnawave` |
| Оплата прошла, доступ не выдан | Админка → Платежи → кнопка «Проверить» у платежа. Воркер сам дожимает такие платежи, как только Remnawave станет доступна |
| Кнопка «Проверить подключение» ЮKassa/Platega показывает ошибку | Неверные shopId/ключ; для Platega — проверьте Merchant ID и секрет |
| Нет доступа к GitHub при установке Remnawave | Скрипт скачивает compose с `raw.githubusercontent.com`; проверьте, что сервер выходит в интернет |
| Забыт пароль панели Remnawave | `/opt/remnawave/credentials.env` (если ставили скриптом) |

## 8. Безопасность — короткий чек-лист

- Включите 2FA в админке и в панели Remnawave.
- Отключите вход по паролю по SSH, используйте ключи; включите `ufw` (22, 80, 443).
- Не публикуйте `deploy/.env`, `CREDENTIALS.txt` и бэкапы; после первой записи паролей удалите `CREDENTIALS.txt` с сервера.
- Регулярно обновляйте систему: `apt-get update && apt-get upgrade`.
- Права в админке: «Владелец» — всё; «Администратор» — всё кроме настроек и админов; «Поддержка» — пользователи и платежи; «Аналитик» — только просмотр.

## 9. Ручная установка (без скрипта)

Для тех, кто хочет контролировать каждый шаг:

```bash
cp deploy/.env.example deploy/.env       # заполните домены, секреты, токен бота
docker network create remnawave-network   # если Remnawave ещё не установлена
cd deploy && docker compose up -d --build
docker compose exec api node dist/cli.js create-admin you@example.com
```

Если Remnawave стоит на этом же сервере, добавьте в `deploy/caddy.d/panel.caddy`:

```
panel.example.com {
	reverse_proxy remnawave:3000
}
sub.example.com {
	reverse_proxy remnawave-subscription-page:3010
}
```
