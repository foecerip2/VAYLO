# Plan: VAYLO Android — Фаза 1 «Валидация и прототип»

## Summary
Снять главные неизвестные до начала разработки Android-приложения: подтвердить вход через бота из нативного клиента, подтвердить передачу подписки в Happ/Hiddify/Incy/Karing через Android Intent, выбрать канал распространения и собрать данные о клиентах для метрик. Результат фазы — решение «идём/не идём» и обновлённый PRD, а не готовый продукт.

## User Story
As a владелец VAYLO,
I want убедиться, что вход, подключение и распространение Android-приложения реально работают,
So that я не вкладываюсь в разработку на непроверенных предположениях.

## Problem → Solution
PRD держится на предположениях (формат deep link, вход вне Mini App, канал дистрибуции, боль клиентов) → каждое предположение проверено на устройстве или источнике и зафиксировано в PRD как факт либо как отклонённое.

## Metadata
- **Complexity**: Small (код минимальный, основная работа — проверки и решения)
- **Source PRD**: `.claude/PRPs/prds/vaylo-android-app.prd.md`

## Patterns to Mirror

Код VAYLO в этой фазе не меняется, поэтому образцы нужны прототипу и документам.

### DEEP_LINK_FORMATS
```ts
// SOURCE: apps/app/src/lib/clients.ts (deeplink)
happ:     (u) => `happ://add/${u}`
hiddify:  (u) => `hiddify://import/${u}`
incy:     (u) => `incy://import/${u}`
karing:   (u) => `karing://install-config?url=${encodeURIComponent(u)}&name=VAYLO`
streisand:(u) => `streisand://import/${u}`
```
Прототип обязан использовать те же строки. Отличие допустимо только как результат проверки и фиксируется в документе.

### AUTH_FLOW
```ts
// SOURCE: apps/api/src/routes/public.ts:153-170
POST /api/v1/auth/tglink/start  -> { token, url, expiresInSec: 600 }   // url = https://t.me/<bot>?start=auth_<token>
GET  /api/v1/auth/tglink/:token -> { status: 'pending' | 'expired' | 'ok', accessToken? }
```
Токен одноразовый: после `ok` запись удаляется, повторный запрос вернёт `expired`.

### ERROR_HANDLING
```ts
// SOURCE: apps/app/src/lib/api.ts (ApiError, errorText)
// Сервер возвращает JSON с текстом; клиент оборачивает в ApiError(status, message, code)
// и показывает пользователю friendlyErrorMessage, а не сырой ответ.
```

### TEST_STRUCTURE
```ts
// SOURCE: apps/api/test/appNotices.test.ts:1-12
// vitest; перед тестами пересоздаётся схема БД, моки внешних сервисов лежат в globalThis.__mocks,
// HTTP проверяется через app.inject({ method, url: '/api/v1/...' }).
```
Для этой фазы новых тестов API не требуется (код не меняется).

## Step-by-Step Tasks

### Task 1: Свериться с официальными источниками по deep link
- **ACTION**: Для happ, hiddify, incy, karing найти официальное описание схемы импорта подписки на Android.
- **IMPLEMENT**: Таблица «клиент / схема / источник / совпадает ли с `clients.ts`» в `docs/android/VALIDATION.md`.
- **MIRROR**: DEEP_LINK_FORMATS.
- **GOTCHA**: Сторонние зеркала и обзоры не считать источником; брать репозиторий или сайт разработчика клиента. Если официального описания нет, отметить «подтверждается только устройством».
- **VALIDATE**: В таблице нет строк без источника или явной пометки.

### Task 2: Собрать одноразовый прототип Android
- **ACTION**: Создать минимальный проект (Kotlin, один экран) вне основного кода.
- **IMPLEMENT**: Кнопка «Войти» вызывает `POST /auth/tglink/start`, открывает `url` через Intent `ACTION_VIEW`, затем опрашивает `GET /auth/tglink/:token` раз в 2 секунды до `ok` или `expired`; после входа показывает `GET /subscription` (state, daysLeft, subUrl); кнопка «Подключиться» вызывает Intent с deep link выбранного клиента.
- **MIRROR**: AUTH_FLOW, ERROR_HANDLING.
- **IMPORTS**: Только стандартные библиотеки Android и HTTP-клиент по выбору; зависимости не тянуть без нужды.
- **GOTCHA**: (1) На Android 11+ для проверки установленного клиента нужен `<queries>` с нужными схемами или пакетами. (2) Срок жизни токена входа 10 минут. (3) JWT хранить только в памяти прототипа, не писать в лог. (4) Тестовый сервер: использовать стенд из README (`devstack`), а не боевые данные клиентов.
- **VALIDATE**: Сборка проходит, вход проходит на реальном устройстве и эмуляторе с установленным Telegram.

### Task 3: Проверить вход через бота
- **ACTION**: Пройти весь поток на устройстве; отдельно проверить сценарии отказа.
- **IMPLEMENT**: Записать результат для: Telegram установлен и авторизован; Telegram не установлен; пользователь не подтвердил в течение 10 минут; повторное открытие прототипа с сохранённым токеном; забаненный пользователь; включённая проверка подписки на канал (`gate`).
- **MIRROR**: AUTH_FLOW.
- **GOTCHA**: Сообщение бота сейчас говорит «Вход на сайт …» (`apps/bot/src/bot.ts:736+`); для приложения формулировка вводит в заблуждение. Зафиксировать как замечание для фазы 2, не править в этой фазе.
- **VALIDATE**: Для каждого сценария указан фактический результат и вывод.

### Task 4: Проверить передачу подписки в клиент
- **ACTION**: Для каждого клиента, доступного на Android, проверить Intent на реальном устройстве.
- **IMPLEMENT**: Таблица: клиент / версия / открывается ли / добавляется ли подписка / требуется ли ручное подтверждение / поведение, если клиент не установлен. Проверить `subUrl` с символами, требующими кодирования.
- **MIRROR**: DEEP_LINK_FORMATS.
- **GOTCHA**: Telegram не пускает кастомные схемы в кнопки (см. комментарий в `Import.tsx`), но из нативного приложения Intent должен работать; если нет, использовать страницу-мост `/import?client=..&url=..` через Custom Tabs. Клиенты могут показывать подтверждение перед добавлением профиля.
- **VALIDATE**: Хотя бы один клиент подтверждён как рабочий, либо зафиксирован запасной путь (копирование ссылки, QR).

### Task 5: Выбрать канал распространения
- **ACTION**: Изучить текущие правила и риски трёх каналов: прямой APK с сайта, RuStore, Google Play.
- **IMPLEMENT**: Таблица «канал / требования к VPN-приложениям / риск блокировки / обновления / вывод» в `docs/android/VALIDATION.md`, с датой проверки.
- **GOTCHA**: Не утверждать статус по памяти: правила меняются. Для каждой строки указывать источник и дату. Если источник не найден, писать «не проверено».
- **VALIDATE**: Выбран основной и запасной каналы, либо явно записано, что решение за владельцем.

### Task 6: Собрать данные для метрик
- **ACTION**: Получить у владельца или из админки базовые числа.
- **IMPLEMENT**: Запросить: число активных клиентов, доля Android (по данным в админке/аналитике, если есть), главные причины обращений в поддержку по подключению, конверсия «оплата → первое подключение», если это уже измеряется (`services/analytics*.ts`, `routes/admin/analytics.ts`).
- **GOTCHA**: Данные о клиентах не копировать в репозиторий и не выносить в документ в персонифицированном виде; только агрегаты.
- **VALIDATE**: В PRD заменены «TBD - needs baseline» на числа или остаются явно как «данных нет».

### Task 7: Подвести итог и обновить PRD
- **ACTION**: Сформировать решение «идём / идём с изменениями / не идём».
- **IMPLEMENT**: Раздел «Итог» в `docs/android/VALIDATION.md`; в PRD фаза 1 → `in-progress`/`complete`, колонка PRP Plan → путь к этому плану, обновить «Open Questions» и «Technical Risks».
- **VALIDATE**: PRD не содержит предположений, уже проверенных в этой фазе, как непроверенных.

## Testing Strategy

### Unit Tests
Код VAYLO не меняется, новые автотесты не нужны. Проверка ручная, на устройствах.

| Проверка | Вход | Ожидаемый результат | Edge Case? |
|---|---|---|---|
| Вход через бота | Telegram установлен, подтверждение в боте | `status: ok`, токен выдан | Нет |
| Истёкшая ссылка входа | Подтверждения нет 10 минут | `status: expired`, понятное сообщение в прототипе | Да |
| Повторное использование токена входа | Второй запрос после `ok` | `expired` | Да |
| Активная подписка | `GET /subscription` | Поля `state`, `daysLeft`, `subUrl` заполнены | Нет |
| Нет подписки | Новый пользователь | `state: none`, `subUrl: null` | Да |
| Подключение, клиент установлен | Intent с deep link | Клиент открыт, подписка предложена к добавлению | Нет |
| Подключение, клиент не установлен | Intent без обработчика | Нет падения, показан запасной путь | Да |

### Edge Cases Checklist
- [ ] Telegram не установлен
- [ ] Нет сети во время опроса входа
- [ ] Токен входа истёк
- [ ] Забаненный пользователь (ответ 403)
- [ ] Включена проверка подписки на канал
- [ ] `subUrl` содержит символы, требующие кодирования
- [ ] Клиент не установлен
- [ ] Разные версии Android (минимум одна 11+ и одна 13+)

| Правила сторов нельзя достоверно установить из открытых источников | M | Средний | Помечать «не проверено» и спрашивать владельца или поддержку стора |

## Notes
- Эту фазу выполняет не агент в одиночку: нужны реальное Android-устройство, Telegram-аккаунт и доступ владельца к данным. Агент может подготовить прототип и документы, но пройти проверки на устройстве не сможет.
- Существующие клиенты в `client_apps` (админка) уже хранят статус доступности в магазине для Android; приложению стоит читать их из `/config`, а не хардкодить.
- Страница `/import` уже реализует мост; её поведение — эталон для запасного пути.
- Подтверждение входа в боте названо «Вход на сайт …»; для приложения нужен отдельный текст (фаза 2).
