# Ежедневная очистка сервера VAYLO

Скрипт vaylo-cleanup-daily.sh предназначен для сервера бота/мини-приложения (Ubuntu с systemd). Обновлять Docker-образы приложения не требуется.

1. Загрузите скрипт в любой каталог сервера, например /root. Перейдите в этот каталог.
2. Предпросмотр действий, без удаления:

```bash
sudo bash vaylo-cleanup-daily.sh --dry-run --dir /opt/vpn-platform
```

3. Установите ежедневное расписание:

```bash
sudo bash vaylo-cleanup-daily.sh --install --dir /opt/vpn-platform
```

Установщик сохранит самостоятельную копию в /usr/local/sbin/vaylo-cleanup-daily и создаст vaylo-cleanup-daily.service/.timer. Исходный загруженный файл после установки для работы таймера не нужен.

Запуск — каждый день в 04:15 **по часовому поясу сервера**. Часовой пояс виден через timedatectl. Если сервер был выключен в это время, Persistent=true запускает пропущенную очистку после включения. Сразу после установки таймер также может выполнить пропущенный запуск.

Повторная установка обновляет тот же таймер. Старое root-задание cron с меткой vpn-platform-cleanup удаляется; ежедневный бэкап и остальные cron-задания сохраняются. Базы, контейнеры и сервисы приложения установщик не перезапускает.

## Что очищается

- Висячие (без тега) Docker-образы с меткой проекта vpn, созданные более 7 дней назад. Тегированные образы :local и :prev для отката остаются.
- Старый неиспользуемый кэш Docker-сборки, старше 7 дней, с порогом хранения кэша 1 ГБ. Этот кэш общий для Docker на сервере; при последующей сборке недостающие слои будут созданы/скачаны заново.
- Скачанные установочные пакеты в кэше apt. Установленные программы не удаляются.
- Архивы системного журнала journald: ограничение 7 дней/200 МБ. При большом объёме журнала ограничение размера может сократить доступную историю.
- Временные файлы внутри /tmp и /var/tmp по существующим правилам хранения ОС, через systemd-tmpfiles. Каталог самого проекта исключён.

Контейнеры, Docker-тома, базы, Redis, сетевые настройки, SSH-ключи, .env, CREDENTIALS.txt, бэкапы проекта и скачанные релизные архивы не удаляются. Скрипт не обнуляет активные Docker-логи; в compose проекта уже задана их ротация 10 МБ × 3 файла.

Одновременно работает только один запуск очистки. При активном бэкапе, установке или восстановлении запуск пропускается. Приоритет CPU/диска понижен; системный сервис ограничен 5 минутами. Реальное количество освобождённого места зависит от накопленного кэша.

## Проверить расписание и журнал

```bash
systemctl list-timers --all vaylo-cleanup-daily.timer
journalctl -u vaylo-cleanup-daily.service -n 60 --no-pager
```

Ручной запуск установленной очистки:

```bash
sudo systemctl start vaylo-cleanup-daily.service
```

Отключить автоматический запуск:

```bash
sudo systemctl disable --now vaylo-cleanup-daily.timer
```

В рабочей копии исходного проекта обновлены scripts/cleanup.sh и установка ежедневного расписания в scripts/install.sh, чтобы будущие сборки сохраняли этот режим. Для текущего сервера достаточно самостоятельного скрипта выше.

## Проверки

Синтаксис Bash, валидация обоих systemd unit-файлов и 7 сценариев в изолированном каталоге: предпросмотр без мутаций, допустимые команды очистки, сохранность .env/бэкапов/credentials, блокировка параллельных запусков и бэкапа, некорректные параметры, повторная установка расписания с сохранением чужих cron-заданий.

Команды очистки в тестах заменялись заглушками. На рабочем VPS в этой сессии скрипт не устанавливался и не запускался.
