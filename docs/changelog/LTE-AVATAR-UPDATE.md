# VAYLO v40 — устройства, отдельный LTE-трафик и фото профиля

## Поведение

Общий VPN-трафик безлимитный при подключённой интеграции LTE. Базовый пакет белых списков — 5 ГиБ. Считается только расход ноды №2. Скользящее окно и историческая нижняя граница 26.10.2026 сохранены из предоставленного lte-quota.sh:

- расход: nodes_user_usage_history, node_id=2, created_at >= GREATEST(DATE '2026-10-26', CURRENT_DATE - 29);
- дополнительные ГБ: vaylo_lte_extra, granted_on >= CURRENT_DATE - 29;
- доступ к Internal Squad с именем LTE: только ACTIVE, без vaylo_lte_optout и с остатком трафика.

Это не сброс по годовщине регистрации и не фиксированный календарный месяц. Дополнительный пакет перестаёт учитываться в начале даты granted_on+30 в часовом поясе БД. Отображается ближайшая дата истечения. Дата расхода/лимита берётся из БД, а не из нарисованного счётчика.

## Покупки и управление

В админке → Докупки: товары «Устройства» и «Трафик LTE · белые списки», количество, цена, включение/выключение, журнал заказов с различием оплаты и выдачи. Есть ручная бесплатная выдача LTE по Telegram ID с обязательной причиной и аудитом. Устройство расширяет существующий лимит при активной подписке. LTE-пакет не меняет общий trafficLimitBytes.

Платёж сохраняет снимок товара. При выдаче LTE его UUID записывается в Remnawave-БД в vaylo_lte_orders. Повторный webhook/повтор после сбоя локального commit не создаёт второй пакет. Срок отсчитывается от первой успешной внешней выдачи. Если после начисления внешний вызов восстановления группы или локальный commit не завершился, повтор использует тот же UUID. До оплаты проверяется подключение интеграции; при недоступности БД продажа не проходит. Явный opt-out блокирует покупку и ручную выдачу.

При исчерпании/истечении LTE группа снимается фоновым заданием раз в 10 минут, как в прежнем cron. После выдачи пакета восстановление выполняется сразу. При продлении и докупке устройств список групп снова проверяет LTE-квоту; исчерпанная LTE не должна возвращаться в обход ограничения. Основная группа подписки должна отличаться от LTE.

Старые товары общего трафика и локаций сохранены как совместимость с историей заказов. Они не превращаются автоматически в LTE-пакеты. При включённой LTE-политике докупка общего трафика заблокирована. В форме нового товара основные варианты — устройства и LTE.

## Mini App и бот

В Mini App на главной и в профиле: общий безлимит отдельно от LTE, использовано/всего/остаток, объём докупленного пакета и ближайшая дата истечения, переход к покупке. После оплаты обновляются запросы профиля/подписки. В текстовом статусе бота — отдельная строка LTE с фактическим остатком. При сбое LTE-счётчика показывается недоступность вместо вымышленных 5 ГБ.

Фото: Профиль → Фото → выбрать JPG/PNG/WebP до 8 МБ. Браузер обрезает по центру до квадрата 384×384 и сжимает в JPEG. Сервер проверяет тип и ограничивает сохранённый файл 512 КБ. Можно заменить/удалить; новое фото появляется в профиле и в аватаре главной страницы. Это фото внутри сервиса, не изменение Telegram-аватара. Оно доступно по случайному непрогнозируемому адресу; замена/удаление закрывает старый адрес на сервере (уже загруженные копии браузер может хранить до 5 минут).

## Установка: сначала обновление, затем подключение LTE

Архив включает предыдущие исправления бота, ежедневную статистику, анимации Orbit, подарки и ручную очистку тестовых пользователей. Миграция 016 добавляет тип товара LTE и хранение аватаров. Установка не удаляет пользователей и не назначает пакеты бесплатно автоматически.

Загрузить vpn-platform-v40-lte-avatar.zip на сервер проекта и выполнить из каталога архива:

```bash
unzip -o vpn-platform-v40-lte-avatar.zip -d /tmp/vaylo-v40 &&
sudo bash /tmp/vaylo-v40/vpn-platform-v40-lte-avatar/scripts/install.sh --update --dir /opt/vpn-platform
```

На сервере, где находятся и vpn-platform, и контейнер remnawave-db:

```bash
sudo bash /opt/vpn-platform/scripts/connect-lte.sh
```

Скрипт рассчитан на предоставленную схему Remnawave/Postgres и общую внутреннюю Docker-сеть remnawave-network (она уже указана для API/worker в compose проекта). Он не публикует порт БД. Создаёт отдельную роль vaylo_lte, техническую таблицу идемпотентности и недостающие LTE-таблицы; сохраняет LTE_DATABASE_URL и LTE_NODE_ID=2 в deploy/.env, не печатая пароль, перезапускает API и worker. Существующие записи vaylo_lte_extra сохраняются. Повторный запуск меняет пароль роли; его не следует запускать одновременно из двух терминалов. Нужны docker, python3 и psql внутри remnawave-db. Создание объектов требует владельца БД в контейнере.

Если Remnawave находится на другом VPS или в другой Docker-сети, автоматический скрипт остановится: нужны доступ API/worker к БД по внутренней сети и переменная LTE_DATABASE_URL, подготовленная роль/таблица. Не открывайте PostgreSQL в интернет ради подключения. До этого пакеты LTE покупать нельзя, а админка покажет «не подключён».

Ваш lte-quota.sh можно оставить: он использует ту же vaylo_lte_extra. Его операторская настройка общего безлимита (UPDATE users SET traffic_limit_bytes=0, traffic_limit_strategy='NO_RESET') должна быть действующей для старых профилей. Новые/продлеваемые профили платформы получают общий безлимит через API Remnawave. Новый worker также синхронизирует группу, включая удаление opt-out; в старом скрипте opt-out проверялся только при добавлении. Прямые изменения членства сохраняют модель вашего скрипта; влияние внутренних кешей конкретной установленной Remnawave необходимо проверить после установки.

Проверить в админке статус LTE, добавить товар «+10 ГБ LTE», выполнить одну ручную выдачу тестовому Telegram ID, сверить 5→15 ГБ в Mini App и наличие в LTE. Цены в скриншотах вымышленные; товары с этими ценами не создаются установщиком.

## Проверки и пределы

238 API-тестов (230 прежних + 8 новых LTE/аватар), 44 теста бота, TypeScript и сборка. LTE-тесты используют настоящую отдельную PostgreSQL с тестовой схемой, воспроизводящей таблицы скрипта: выбор ноды/окна, повтор платежа, возврат/снятие группы, opt-out, истечение пакета, неактивный пользователь, сохранение ограничения при продлении, проверка/ротация аватара. Схема реальной Remnawave и скрипт подключения на вашем VPS здесь не запускались.

Браузер: показ 5→15 ГБ на демоданных, загрузка изображения с реальным преобразованием в JPEG, профиль/главная/магазин/админка, отсутствие ошибок JS и мобильной горизонтальной прокрутки. Скриншоты в lte-delivery демонстрационные. Браузерный тест не выполняет реальный платёж. Рекомендуемая проверка после установки описана выше.
