# v58 — сетевая аналитика, подбор локации, бизнес-аналитика, безопасность проб

Все новые модули выключены флагами (`deploy/.env`, значения `true/false`). Миграции 025–027 применяются сами.

## Что внутри
1. **Токены проб** (`/admin/probe-tokens`, страница «Сеть: аналитика»): хэш в БД, показ один раз, отзыв, срок, журнал аудита. Проба: `NETPROBE_WRITE_TOKEN=... node probe.mjs --api ... --sub ...`. `NETPROBE_SCOPED_AUTH=true` отключает приём общего `INTERNAL_KEY` на `/net/probe-report` — включайте после перехода всех проб на токены.
2. **Инциденты сети** (`NETWORK_INTELLIGENCE_ENABLED`): только по реальному Xray; браузерные замеры показываются отдельно и в инциденты не идут. Алерты: `NETWORK_INCIDENT_ALERTS_ENABLED`.
3. **Подбор локации** (`NODE_RECOMMENDATIONS_ENABLED`): подсказка в Mini App «Локации», только из доступных по тарифу, только при ≥5 свежих замерах; ничего не переключает. Сопоставление с локацией — по названию в «Статус серверов» (без флага/эмодзи) и цели пробы; если названия не совпадают — рекомендации не будет.
4. **Аналитика** (`PRODUCT_ANALYTICS_ENABLED`): выручка/возвраты/ARPPU/MRR-оценка/воронка/когорты из таблицы `payments`; события Mini App — только `miniapp_open`. `bot_start` и `trial_started` в события пока не пишутся (воронка берёт trial из подписок).
5. **Поддержка ИИ** (`SUPPORT_AI_KNOWLEDGE_ENABLED`): база знаний + статус сети в контексте; `GET /admin/support/tickets/:id/triage` — тема и резюме без персональных данных. ИИ по-прежнему ничего не выполняет.

6. **Эксплуатация/интерфейс:** проверка воркера (heartbeat, виден на обзоре), ежедневная чистка старых событий/инцидентов, страница «Подбор локации», блок здоровья на обзоре, статус серверов в Mini App, офлайн-баннер.

## Не проверено
Реальный Xray и SIM, staging, нагрузка, ручной просмотр интерфейса на телефонах, веса подбора локации (гипотеза).
