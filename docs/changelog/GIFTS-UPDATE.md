# VAYLO v35 — открытки и управление подарками

Реализованы выбранные пункты 1 и 2. Внешнего чекера нет.

## Возможности

- После покупки можно оформить открытку: имя получателя, подпись отправителя, поздравление до 400 символов и тема Orbit / Aurora / Pearl. Имена — оформление, а не привязка к конкретному Telegram-аккаунту. Подарок получает первый активировавший код.
- До активации открытку можно редактировать. Одновременное редактирование с другого устройства определяется по версии, чтобы не потерять изменения.
- Получатель сначала видит поздравление, условия и прогноз срока доступа. Переход по ссылке не активирует код.
- Если уже есть действующая платная подписка, подарок добавляет дни, сохраняя её тариф и лимиты. Для нового, истёкшего или пробного доступа применяются условия подарка. Уже оставшиеся дни добавляются по прежним правилам сервиса.
- Повтор успешной активации тем же получателем возвращает сохранённый результат без повторного начисления. Другой аккаунт использовать полученный код не может.
- История покупок и полученных подарков, статусы и даты. Старые оплаченные подарки не исчезают после 100 новых записей.
- Покупатель может заменить код неиспользованного подарка: старые код и ссылка перестают работать, открытка сохраняется. Перед заменой есть подтверждение.
- Админка → Продажи → Подарки: поиск по имени, Telegram ID, ID подарка или платежа, статусы, страницы, покупатель и получатель. Коды в админке не раскрываются.
- Администратор может отозвать неактивированный подарок. Это не возврат денег; возврат оформляется отдельно через действующие платёжные сценарии. Уже активированный доступ автоматически не отзывается.
- Ссылка для браузера хранит код после #, чтобы он не попадал в URL запроса веб-серверу. Старые ссылки ?code= поддерживаются. Переход через вход возвращает к подаркам; приглашение через /start gift_... в боте открывает подарок в Mini App. Данные ожидающего подарка в текущей вкладке сохраняются на 24 часа.

## Установка обновления

Распакуйте архив в отдельную папку и запустите из неё:

```bash
sudo bash scripts/install.sh --update --dir /opt/vpn-platform
```

Используйте свой путь после --dir, если установка расположена иначе. Существующие .env, APP_SECRET, базы и резервные копии сохраняются штатным установщиком. Не заменяйте APP_SECRET: он нужен для расшифровки существующих кодов.

Миграция 013_gift_cards.sql добавляет оформление открыток, версии и результат активации; применяется API автоматически. Существующие подарки сохраняются. Для старых уже активированных подарков исходная дата результата может быть неизвестна: повтор показывает текущую доступную дату профиля, повторного начисления нет.

Права файлов в архиве: 0644, скрипты 0755. Сохранены исправленные владельцы node:node, проверки чтения runtime-файлов в Dockerfile и права чтения статических файлов шлюза.

## Проверки

API: 207 тестов, бот: 31, shared: 8 — всего 246 успешных проверок по пакетам. TypeScript всех пакетов и сборка прошли. Chromium проверил редактор, три темы, отсутствие автоматической активации, одно получение по кнопке и вход гостя. БД и внешние сервисы в тестах изолированы/заменены моками; реальные оплаты и физические устройства не проверялись. На сервер пользователя обновление не устанавливалось.

## Следующие варианты на выбор

1. Скачивание открытки как PNG для пересылки картинкой, с отдельной кнопкой открытия подарка.
2. Отправка к дню рождения или другой дате: расписание, отмена и статус доставки. Только явный выбор отправителя, с учётом доступности адресата боту.
3. Уведомление покупателю, когда подарок получен, и мягкое напоминание о ещё неотправленной открытке.
4. Наборы подарков для команды: несколько отдельных одноразовых кодов и общая история.

Изменение срока действия уже оплаченных кодов и автоматические денежные возвраты в эту версию не включены.
