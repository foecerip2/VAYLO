# VAYLO v44 — исправление очистки триалов и проверка удаления

## Что исправлено

В старом фильтре одновременно требовались trial_used=true и subscriptions.is_trial=true. Поэтому расхождения старых данных скрывали часть пробных аккаунтов. Также любой внешний ID платёжной заявки исключал пользователя навсегда — даже если заявка отменена и не оплачена. Без rw_id старый код мог удалить локальный аккаунт, не проверив оставшийся профиль в Remnawave.

Новая версия:

- Показывает «К удалению», «Почему не попали», «Все пробные», поиск и конкретные причины исключения. Пробная подписка сама подтверждает использование триала, даже если trial_used не установлен. Для старых записей с неверным is_trial учитываются название пробного тарифа, отсутствие plan_id и отдельное подтверждение использования теста. Неизвестный тип доступа не считается автоматически пробным.
- Не исключает аккаунт только из-за статуса блокировки. Средства, реальные оплаты/возвраты, незавершённые платежи, подарки, реферальные начисления, выводы, администраторы и открытая поддержка по-прежнему защищены и видны с причиной.
- Отменённые/истёкшие заявки без оплаты не считаются покупкой. Если есть внешний ID, перед удалением запрашивается статус YooKassa/Platega/Rollypay. Только подтверждённая отмена позволяет продолжить; ошибка связи, незакрытая заявка или найденная оплата сохраняют пользователя.
- Перед удалением ищет профиль по имени, идентификатору подписки (short UUID) и сохранённому числовому ID. Защищает от удаления чужого профиля при переиспользовании ID после восстановления панели. Проверяет срок доступа в самой панели: активная подписка или окончание менее 72 часов назад останавливают очистку.
- После DELETE повторно читает профиль по ID и имени. Пока отсутствие не подтверждено, локальный аккаунт не удаляется. Если панель успела удалить профиль, а локальная транзакция затем откатилась, повторный запуск допускает уже отсутствующий профиль после проверки доступности API.
- После локального удаления проверяет отсутствие старой записи и наличие запрета триала. В результатах показаны удалённые и проверенные, пропуски с причиной, ошибки с этапом проверки.

Речь о локальной учётной записи бота/мини-приложения и профиле VPN в Remnawave. Бот не удаляет Telegram-аккаунт человека и не может удалить чат на его устройстве.

## Кого можно удалить

Нужны подтверждённый использованный триал, Telegram ID и известная локальная дата окончания. После окончания должно пройти **более 72 часов**. Подписка, изменившаяся на платную/неопределённую, не удаляется по предположению.

За один запуск удаляется до 100 подходящих аккаунтов из результатов поиска. Список действует 15 минут. Каждый аккаунт проверяется повторно под блокировкой перед удалением. Поиск с Telegram ID помогает разобрать конкретный пропуск. Установка обновления сама пользователей не удаляет.

## Реестр и запрет повторного триала

Вкладка **«Удалённые · запрет триала»** содержит Telegram ID, дату удаления, время и результаты проверки. Фильтры: все удалённые, вернувшиеся в бот, нуждающиеся в проверке. Кнопка «Проверить» читает локальное состояние и Remnawave, не удаляя вернувшийся аккаунт.

Запрет хранится в trial_cleanup_tombstones независимо от удалённого users и без срока действия. При повторном /start создаётся новый локальный аккаунт с использованным триалом и без повторного бонуса регистрации. Дополнительно:

- API мини-приложения скрывает доступность триала по реестру, независимо от локального флага.
- Серверный POST /subscription/trial проверяет реестр, поэтому старые кнопки бота, прямой запрос и ошибочно сброшенный trial_used не выдают новый тест.
- Старый пользовательский JWT после удаления больше не авторизуется.
- Покупка платного тарифа доступна. Повторная проверка старого удаления отличает новый профиль по UUID и сохраняет его.

Запрет относится к тому же Telegram ID. Это не распознавание одного человека под разными Telegram-аккаунтами. Подарки и другие существующие способы выдачи доступа не заменяются баном аккаунта.

В старых версиях реестр сохранял только Telegram ID. Эти записи уже запрещают новый тест. Новая проверка дополнительно ищет стандартное имя tg_ID; найденный профиль помечается для сверки. При отсутствии старого ID/UUID/имени нельзя достоверно доказать удаление переименованного профиля. Неизвестный результат так и отображается.

## Установка на сервер бота/мини-приложения

Загрузите vpn-platform-v44-trial-cleanup-fix.zip, затем из каталога с архивом:

```bash
unzip -o vpn-platform-v44-trial-cleanup-fix.zip -d /tmp/vaylo-v44 &&
sudo bash /tmp/vaylo-v44/vpn-platform-v44-trial-cleanup-fix/scripts/install.sh --update --dir /opt/vpn-platform
```

Это полный архив с предыдущими изменениями, включая активность LTE. Установщик сохраняет deploy/.env и делает резервную копию. Новая миграция 018_trial_cleanup_verification.sql расширяет существующий реестр; старые запреты не удаляются. SSH-туннель LTE перенастраивать не нужно.

После обновления откройте **Очистка триалов → Почему не попали**, найдите Telegram ID нужного пользователя и проверьте причину. Затем во вкладке «К удалению» подготовьте список, проверьте аккаунты и подтвердите словом УДАЛИТЬ. Результаты сверяются в реестре.

## CLI

Предпросмотр без удаления:

```bash
sudo bash /opt/vpn-platform/scripts/cleanup-trials.sh
```

Явный запуск очистки:

```bash
sudo bash /opt/vpn-platform/scripts/cleanup-trials.sh --apply
```

CLI завершится с ненулевым кодом, если в запуске есть ошибки удаления/проверки.

## Проверка в разработке

Пройдены 266 тестов API (24 сценария очистки), проверка TypeScript всех приложений, сборка и браузерные проверки интерфейса.

Сценарии включают несовпадающие признаки триала, причины исключения, отменённые заявки, ошибку провайдера, потерянный ID, переименованный профиль, переиспользованный ID чужого профиля, ложный успех DELETE, срок доступа в панели, ошибочный URL API, повторный /start, старую кнопку бота и прямой запрос мини-приложения, сброшенный флаг, истёкший JWT, покупку после возвращения и старые записи реестра.

Превью интерфейса сняты на демонстрационных данных. В этой сессии нет доступа к рабочим БД: конкретные пропущенные аккаунты пользователя и удаление на VPS здесь не проверялись.
