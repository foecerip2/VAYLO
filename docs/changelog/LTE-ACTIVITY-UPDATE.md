# VAYLO v43 — активность пользователей LTE

В веб-админке появился раздел **Активность LTE**. Интеграция использует существующее соединение с БД Remnawave через SSH-туннель.

## Возможности

- «Активны сейчас»: пользователи, у которых Remnawave записала трафик на LTE-ноде за последние 5 минут.
- История за сегодня, 7, 30 или 90 дней: кто пользовался LTE, расход за период, число дней с трафиком, последняя запись трафика, остаток квоты и наличие доступа к группе LTE.
- Поиск по имени, Telegram username, Telegram ID, локальному UUID, имени профиля или числовому ID Remnawave.
- История пользователя по дням: объём и время последней записи в каждом дне. Переход в карточку пользователя; обратная ссылка «Активность LTE» в его разделе трафика/докупок.
- Профили, не связанные с локальным аккаунтом платформы, также видны по имени и ID Remnawave.
- Автообновление каждые 30 секунд, когда вкладка открыта. Таблицы и навигация адаптированы для телефона.

## Что означает активность

Источник — nodes_user_usage_history, только LTE_NODE_ID (у вас 2). Индикатор «Трафик ≤ 5 мин» использует updated_at этой ноды: это свежая запись расхода, а не проверка открытого TCP-соединения. Учитывайте задержку опроса ноды и записи данных самой Remnawave. Профиль в группе LTE без трафика не считается активным. Подключение без передачи данных может не отображаться.

Remnawave хранит дневные суммы. created_at — день учёта, а не начало соединения. Поэтому история показывает дни и последнюю запись расхода; точные начало/завершение каждой сессии не выдумываются. На старой схеме без updated_at доступна история по дням, индикатор текущей активности неизвестен.

Дни учитываются по UTC, часы отображаются в часовом поясе браузера (он подписан под таблицей). Суммарные показатели учитывают поисковый запрос. Период влияет на расход и исторический список; индикатор последних 5 минут всегда относится к текущему моменту.

История читается из существующих записей Remnawave, включая доступные записи до установки обновления. Если панель уже очистила старые данные или учёт ноды выключен, восстановить их этот экран не сможет. Раздел читает данные, не меняя пользователей, доступ или квоты Remnawave.

## Настройки

Соединение LTE_DATABASE_URL и LTE_NODE_ID сохраняются. Повторно запускать connect-lte-remote.sh не нужно.

Добавлен необязательный LTE_ACTIVITY_START_DATE, по умолчанию **2026-10-25** — дата, с которой нода №2 обслуживает только LTE по вашему скрипту. Более ранний трафик этой ноды исключён из истории LTE. Если история другого узла началась в другой день, задайте реальную дату YYYY-MM-DD в deploy/.env и пересоздайте API:

```bash
cd /opt/vpn-platform/deploy && docker compose up -d --force-recreate api
```

Дата начала активности не меняет расчёт квоты: сохранены ваш базовый пакет 5 ГиБ, окно 30 календарных дней, действующие докупки и нижняя граница учёта квоты 2026-10-26. Общий VPN остаётся безлимитным.

Раздел доступен администраторам с правом просмотра пользователей (от analyst), обычному пользователю API закрыт. При недоступности БД/SSH показано «Данные LTE временно недоступны», показатели неизвестны; сбой не превращается в нулевой трафик или офлайн всех пользователей.

## Установка

Загрузите vpn-platform-v43-lte-activity.zip на сервер бота/приложения, затем выполните из каталога с архивом:

```bash
unzip -o vpn-platform-v43-lte-activity.zip -d /tmp/vaylo-v43 &&
sudo bash /tmp/vaylo-v43/vpn-platform-v43-lte-activity/scripts/install.sh --update --dir /opt/vpn-platform
```

Установщик сохранит deploy/.env, SSH-конфигурация и сервис туннеля остаются на сервере. Это полный архив проекта с предыдущими изменениями, включая LTE-докупки и аватары. Для этого раздела не нужны новые права роли БД Remnawave или новая миграция; достаточно существующего SELECT на истории и пользователях.

## Проверка

- 250 тестов API, включая сценарии активности, поиска, постраничного вывода, дат, границы LTE-истории, отсутствия updated_at, недоступности источника и прав API.
- Проверка TypeScript всех приложений и сборка монорепозитория.
- Браузер: списки активности/истории, дневная история пользователя, переход в карточку, поиск, мобильная раскладка, потеря соединения и HTTP-ошибка.

Превью сделаны в настоящем интерфейсе на демонстрационных данных. На рабочем сервере обновление в этой сессии не запускалось.
