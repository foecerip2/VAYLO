# VAYLO Orbit — обновление v34

Реализовано выбранное направление B: графит, хромированная орбита и фиолетовые акценты. Внешних сервисов проверки нод в этой версии нет.

## Что изменилось

- Новая главная Mini App с анимированной орбитой, состоянием подписки и одной основной кнопкой. Уменьшение движения в настройках устройства отключает анимацию.
- Четыре основных раздела: Главная, Тарифы, Помощь, Профиль. Баланс доступен с главной и из профиля; бонусы, задания и колесо — из профиля.
- Мастер подключения: выбор устройства → установка рекомендуемого клиента → импорт подписки → инструкция включения VPN. Другие клиенты, ручной импорт, QR-код и сброс ссылки сохранены.
- Раздел помощи: устройство, клиент, оператор и тип проблемы. Сведения можно скопировать или перенести в черновик обращения. Автоматической отправки обращения нет.
- Подарки: покупка тарифов с баланса или через подключённые платёжные методы, одноразовый код, отправка через Telegram, активация на аккаунте получателя. Срок доступа начинается при активации; при действующей подписке дни добавляются по существующим правилам сервиса.
- Приветственный баннер бота `apps/app/public/orbit-bot.png`, новые кнопки подарков и помощи. Фото, загруженное через админку, имеет приоритет над новым баннером. Существующий сохранённый текст приветствия не перезаписывается.
- Внутренний мониторинг: настраиваемый интервал от 60 до 3600 секунд, прежний порог неудач и уведомления о восстановлении. В уведомлении об отключившейся ноде перечисляются резервные ноды, связанные с панелью. Это не измерение доступности из сети пользователя и не автоматическое переключение VPN-клиента.

## Исправления

- Личные и административные команды бота ограничены личными чатами.
- Штатные бот и Mini App передают идентификатор покупки. API сохраняет его в платеже, сверяет параметры и сериализует повторы через PostgreSQL: повтор возвращает ранее созданный платёж. Старые сторонние клиенты без заголовка `Idempotency-Key` сохраняют прежнюю семантику создания платежа.
- Вход администратора через Telegram сохраняет `session_epoch`.
- В webhook-режиме бот требует непустой `WEBHOOK_SECRET`.
- Фото приветствия отправляется и при пустом тексте; длинный текст не обрезает HTML-сущности.
- Наличие подписки больше не выдаётся за подтверждение работающего VPN.
- Каталожные локации не считаются работающими нодами. У старого статуса есть метка устаревания и предельный возраст кэша.
- Расчёт стоимости не принимает запоздавший ответ от другого товара или промокода. Оплата недоступна до завершения расчёта.
- Ошибка соединения на странице платежа позволяет повторить проверку и не утверждает, что платёж не найден.
- Проверка HTTP-узлов провайдеров учитывает ошибки сервера, но не считает ожидаемые ответы 401/403/404/405 доказательством аварии. В деталях указано, что проведение платежа не проверялось.

## Подарки и возвраты

Код выпускается в одной транзакции с выдачей оплаченной покупки, хранится зашифрованным и показывается только покупателю. Активация блокирует строку подарка; повторная одновременная активация отклоняется. Сбой Remnawave откатывает активацию, поэтому код можно использовать повторно после восстановления панели.

При возврате платежа подарочный код отзывается. Если его уже активировали, администратору приходит уведомление с ID получателя: вопрос отзыва уже выданного доступа решается вручную, как и для обычных возвратов тарифов. Автоматическое списание дней у получателя не выполняется.

Подарочный код даёт доступ тому, кто его активирует первым. Не публикуйте его в общих чатах. Сохраняйте исходный `APP_SECRET` вместе с резервными копиями: он нужен для расшифровки настроек и кодов.

## Обновление существующей установки

В архиве исходники, без `node_modules`, рабочих `.env`, данных БД и готовых Docker-образов.

1. Распакуйте обновление в отдельный каталог на сервере.
2. Сохраните текущие `deploy/.env`, `deploy/caddy.d`, данные и резервные копии установленного сервиса. Не заменяйте секреты значениями из `.env.example`.
3. Из каталога обновлённых исходников запустите штатный установщик:

   ```bash
   sudo bash scripts/install.sh --update
   ```

   При нестандартном пути установки передайте штатный параметр `--dir` (его имя и доступные параметры можно проверить через `bash scripts/install.sh --help`). Установщик синхронизирует исходники, делает резервную копию и пересобирает контейнеры.

4. При запуске API автоматически применяется миграция `012_orbit_gifts.sql`: добавляются идентификаторы покупок и таблица подарков. Не применяйте её вручную повторно. Откат исходников сам по себе не откатывает миграции и новые данные.
5. В админке проверьте приветственный текст/изображение, способы оплаты и настройки мониторинга. Для webhook-бота проверьте наличие `WEBHOOK_SECRET`.
6. Проверьте на тестовом аккаунте: `/start`, триал/обычную покупку, импорт в VPN-клиент, покупку подарка, активацию другим аккаунтом и обращение в поддержку.

## Исправление упаковки после EACCES

Новый SQL-файл и изображения в первоначальном архиве имели права 0600. Сборка от root проходила, но пользователь node не мог прочитать миграцию при запуске контейнера. Исправлено:

- файлы исходного ZIP упаковываются с правами 0644, shell-скрипты — 0755;
- API и бот копируются в runtime-образы с владельцем node:node;
- при Docker-сборке пользователь node проверяет чтение SQL-миграций и стартовых JS-файлов;
- статические файлы шлюза получают права чтения и прохода по каталогам.

Если первоначальный архив уже распакован на сервере, достаточно исправить права файлов в apps/api/migrations, apps/app/public и apps/admin/public в распакованной папке, затем снова запустить штатный install.sh --update. Менять пользователя контейнера на root не требуется.

Регрессия проверена в Docker на Node 22: исходный способ копирования воспроизводит EACCES на SQL с правами 0600; исправленные runtime-этапы API/бота читают файлы от node (UID 1000). API применил все 12 миграций в отдельной тестовой БД и ответил 200 на /api/v1/health. Полная повторная сборка сетевого builder-этапа для этой проверки не выполнялась: использованы ранее собранные и развёрнутые pnpm deploy артефакты.
